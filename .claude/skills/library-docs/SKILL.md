# ライブラリ docs の書き方

お手本は ac-library の `document_ja`（dsu.md, fenwicktree.md, segtree.md）。
ドキュメントには what（何をするか・引数・戻り値・制約・計算量）だけを書く。why や how は書かない。

## 構成

```
---
title: <英語名>
documentation_of: <path>.hpp
---

### 概要
- <1 文>

### 使い方
- `<シグネチャ>`: <1 文>

### 制約
- <不等式>

### 計算量
- `<関数>`: $\mathcal{O}(\cdot)$
```

- 問題例を付けるなら `### 問題例` として最後に置く。
- 制約や計算量が無い関数しかなければ節ごと省く。

## 文

- 常体で統一する（〜する / 〜を返す）。「〜します」は使わない。
- 1 項目 1 文。補足は 2 文目に事実だけ書く。
- 読点は 1 文に 1 つまで。
- 取得系は「<具体的な対象> を返す」。目的語は具体的に書く（`a[l] + ... + a[r - 1]`、「頂点 `v` の番号」）。「値を返す」のような抽象語は使わない。
- 変更系は「<対象> を <どうする>」（「mod を `m` に設定する」「辺 $(a, b)$ を追加する」）。
- デフォルト引数はシグネチャに書く（`<id = -1>`、`(n, root = 0)`）。文で「省略時は」と書かない。
- 制約は不等式だけ書く（$0 \le p < n$）。「素数でなくてもよい」のような文は、制約に $1 \le m$ と書けば伝わる。
- 計算量は結論だけ。ならし計算量は「償却」と書く。前計算と 1 回の計算が分かれるときは「前計算 $\mathcal{O}(N)$、クエリ $\mathcal{O}(1)$」。

## 書かないもの

- 仕組み（「素因数分解して CRT で合成する」）
- 利点・用途・比較（「〜と同じ流儀」「〜に便利」「〜ができる」）
- 内部状態の説明（「テーブルは破棄される」「キャッシュもリセットされる」）
- 使う人への注意書きの節。必要な事実は該当する関数の 2 文目に書く
- 呼び出しを短くするイディオムや別名
- 新しい用語。既存の語（区間、頂点、辺番号）で書く

## 書く前と後

1. 同じディレクトリの既存 doc を 1 つ読み、長さと文末を揃える。
2. 書いた後、各文について「これは what か」を確かめる。why や how なら消す。
3. 「返す」の目的語が具体的か、読点が 1 つ以下か、を確かめる。

## 例

```
### 使い方
- `dsu(n)`: $n$ 頂点 $0$ 辺の無向グラフを作る。
- `merge(a, b)`: 辺 $(a, b)$ を追加し、代表元を返す。
- `same(a, b)`: 頂点 `a`, `b` が連結かを返す。
- `leader(a)`: 頂点 `a` の属する連結成分の代表元を返す。

### 制約
- $0 \le a, b < n$

### 計算量
- `merge`, `same`, `leader`: 償却 $\mathcal{O}(\alpha(n))$
```
